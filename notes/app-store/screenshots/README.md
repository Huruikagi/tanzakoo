# スクリーンショット

**Mac実機の撮影は [半自動スクリプトの手順](mac-capture.md) を使える。** MacへのCodex追加インストールは不要。既存のアプリで画面を整えてEnterを押すと、撮影・サイズ検査・記録保存を行う。2026-10-01に [日英6枚の実機撮影原本と確認記録](native/README.md) を受領・保存した。日本語変更提案の見切れは追加の再撮影で解消済み。最終提出ビルドとの一致確認が残る。

`previews/` の6枚は、build 2のフロントエンドをWindowsのブラウザーで表示した**構図案**。架空のカード・会話・保留提案をfixtureとして読み込んでいる。AIによる実処理、Macの描画、実際のStoreビルドの動作確認を示すものではない。画像内にもその旨を表示している。**このPNGをApp Store Connectへ提出しない。**

## 提出用の撮影案

追加の装飾やキャッチコピーを焼き込まず、使用中の画面を3枚、日英で用意する。各画像の役割は次のとおり。

| 順序 | 画面                       | 伝えること                         | 撮影時の状態                                                                           |
| ---- | -------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------- |
| 1    | ボードとカード詳細         | 思いつきから決定まで見渡せる       | チャットを閉じ、4列に短いカードを配置。「まずは一人で使う」を選択                      |
| 2    | ボード・変更提案・会話     | AIの変更は内容を確かめて適用できる | AIで「今日の一歩を選ぶ」の変更提案を作り、差分と「適用する」を表示。撮影前に適用しない |
| 3    | Markdownエクスポートの確認 | 決まった内容を次の作業へ渡せる     | 「決めたこと」に2枚置き、エクスポート画面を開く。個人の保存先は見せない                |

使用する架空プロジェクトは「週末の小さなアプリ / A small weekend app」。[preview.tsx](preview.tsx) の `entries` と `project.memory` に日英の入力用サンプルを保存した。英語UIへの切り替えだけではカード本文は翻訳されないため、英語の撮影には英語サンプルで別プロジェクトを作る。AIの返答は実際の返答を使用し、fixtureの文章と一致する必要はない。

1. 最終提出予定のアプリをApple SiliconのMacで起動し、撮影専用プロジェクトを用意する。私用のカード、メール、アクセスコード、実ファイルのパスを含めない。
2. 画面内に必要な操作が収まり、本文が読めるサイズにする。AppleのMac用指定は16:10、1280×800・1440×900・2560×1600・2880×1800。Retinaでは論理サイズではなく保存したPNGのピクセル数を確認する。
3. Macのスクリーンショットでアプリの表示範囲を撮影。ログイン画面、空ボード、OSの通知、別のアプリ、透明なウィンドウ影を含めない。指定サイズになるよう撮影範囲を合わせ、画面を引き伸ばさない。
4. PNGまたはJPEG、アルファチャンネルなしで保存し、文字の切れ・スクロール位置・サイズを確認する。日本語3枚と英語3枚を、それぞれのローカライズへ追加する。
5. 記録にアプリの版・ビルド、macOS、撮影日、画像サイズを残す。ブラウザー構図案は提出用フォルダに混ぜない。

公式仕様: [Apple Screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/)（2026-09-28確認）。Mac画像は1〜10枚。今回は説明の重複を避けて3枚とする。

## 構図案の再生成

元のアプリのコードを変更せず、`git archive` で `2a5adab1365b2c239106af71662045442ff33180` を `.local/store-preview-build2` のような作業ディレクトリに展開する。現行HEADで代用すると、未アップロードの機能が写る可能性がある。

1. このフォルダの `preview.html` / `preview.tsx` を、展開先でも `notes/app-store/screenshots/` に置く。
2. 対応する依存関係を利用できる状態にし、展開先で `mise exec -- pnpm exec vite --host 127.0.0.1 --port 1466 --strictPort` を実行する。今回の構図確認では既存の `node_modules` を共有しており、配布ビルドの依存再現検証ではない。
3. Playwrightモジュールのfile URL、ローカルサーバーURL、出力先を指定して `capture-preview.mjs` を実行する。既存のCodex同梱PlaywrightとEdgeを利用でき、新しい依存をプロジェクトに追加する必要はない。

```text
mise exec -- node notes/app-store/screenshots/capture-preview.mjs <playwright-module-file-url> http://127.0.0.1:1466/ notes/app-store/screenshots/previews
```

fixtureはTauriのIPCをモックし、ネイティブ機能やAI・relayへリクエストを送らない。プレビュー入口を製品のHTMLに組み込まない。
