# 列間ドラッグのアニメーション調査

2026-09-19。ユーザーから「アイデアの山 → 検討する」の移動途中だけ表示がおかしいとの報告。

## 結果

同じ `Board` コンポーネントを使うローカルのブラウザ検証画面で再現した。カードの移動先と最終状態は正しいが、ドロップ後にカードが縮小しながら左上へ飛び、約300ms後に移動先へ現れる。

最初の調査で再現し、同日の追加依頼で以下の修正を実装した。検証ではSQLite保存を模擬した通信に置き換えたため、実アプリの保存時間そのものを測定した結果ではない。ユーザーの実データは変更していない。

## 原因

- `Board.tsx` は `onDragOver` の `preventDefault()` でライブラリの先行並べ替えを止めている。
- ドロップ時は非同期の `act(updateCard)` を開始し、保存結果を受け取ってから `snapshot` を差し替える。
- 一方、dnd-kitの標準ドロップアニメーションはその保存を待たず、元の要素／プレースホルダーの位置に向けて250msの移動を始める。
- 保存結果でカードが別の列に描き直されると、アニメーション中の要素のライフサイクルと競合する。40msの保存遅延では、幅278.5px・高さ137.9pxからそれぞれ0pxへの縮小と、左上方向への移動が二度目のアニメーションとして記録された。
- CSSの色や影のtransitionではなく、ドラッグライブラリによるサイズ・位置アニメーションとReactの列間再描画が重なる問題。

## 再現条件・証拠

- ローカル検証画面：`.local/motion.html` / `.local/motion.tsx`
- 再現スクリプト：`.local/inspect-motion.mjs`（既存のランタイムに含まれるPlaywright、ヘッドレスEdge）
- Chromiumの `Element.animate()` と `requestAnimationFrame` でキーフレーム・カード位置を記録。
- 保存遅延0ms：今回の試行では移動先へ通常の着地。
- 保存遅延40ms：戻りアニメーションの途中にサイズ0へのアニメーションが始まり、縮みながら左上へ飛ぶ。
- 保存遅延300ms：元の列へ戻ってから、保存完了で移動先へ瞬間移動する。
- `.local/motion-evidence/trace-{0,40,300}.json` に計測値、同フォルダーの `before` / `drag` / `drop` / `mid` / `after` PNGに画面を保存。

## 実装した修正

- `DragOverlay` を使い、ドラッグ中の見た目を元のカード要素から分離した。カードの描画部分は共通化し、オーバーレイは操作・読み上げの対象から外した。
- `dropAnimation={null}` で、破棄される元要素に向かう終了アニメーションを停止。ドロップ直後にローカルの配置プレビューを表示する。周囲のカードが詰まる並べ替えアニメーションは維持する。
- 保存済みsnapshot自体は先行変更しない。プレビューは列と位置だけを上書きし、本文などの更新を巻き戻さない。
- 保存成功時は確定snapshotへ移行、失敗時はプレビューを解除して元の配置へ戻す。エラーは既存のワークスペース通知に載る。
- 保存待ちの間は次のドラッグ開始を止め、古いrevisionで移動を連続送信しない。
- 先行DOM並べ替えを止める `onDragOver.preventDefault()` は維持した。新しい依存関係は追加していない。

## 修正後の検証

- `pnpm check` 通過：UIテスト22件、lint・整形・型検査・Viteビルド。追加した3件では保存前の表示、保存失敗と他の変更の保持、連続ドラッグの抑止と解除、キャンセル／対象なしのドロップを確認。
- ヘッドレスEdgeで保存遅延0・40・300msを再実行。移動カードのサイズ0への縮小や元の列への戻りは消え、保存完了前から移動先に表示された。記録されたアニメーションは元の列に残るカードの詰め直しのみ。
- `.local/motion-fixed/` に修正後のフレーム計測と画面、`.local/motion-evidence/` に修正前の記録を保持。
- `.local/verify-motion-fixed.mjs` で既存カードへの列間移動、列内並べ替え、Escキャンセル、1000ms後の保存失敗と復元、キーボードでの列間移動を確認。ページ実行エラーなし。
- `.local/` はGit管理外の検証データ。ネイティブ実行ファイルの再生成と実SQLiteでの操作試験は今回行っていない。

参考：[dnd-kitの状態管理ガイド](https://dndkit.com/react/guides/sortable-state-management/)。実際の挙動はインストール済み `@dnd-kit/dom` 0.5.0の `runDropAnimation` と上記記録を根拠にした。
