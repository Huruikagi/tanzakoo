# 応答完了のデスクトップ通知

設定の「一般」から、AIの応答完了通知を選ぶ。全プロジェクト共通で、初期値は「非アクティブ時のみ」。設定はアプリのプロジェクトカタログDBへ保存する。

| 設定               | 通知する条件                                                                 |
| ------------------ | ---------------------------------------------------------------------------- |
| 通知しない         | 自動通知しない                                                               |
| 非アクティブ時のみ | 応答の保存が終わった時点でTanzakooのウインドウが非アクティブ。最小化中も含む |
| 常に通知する       | アクティブでも通知する                                                       |

正常終了した応答1回につき1通知。AIが質問を提示して回答待ちになった場合も含む。停止・通信失敗・トークン上限などによる打ち切り・過去の会話の再表示では通知しない。通知本文に回答やカードの内容は含めない。

Macで未許可の場合は、設定画面の「通知を許可する」から許可する。拒否後はOSの通知設定でTanzakooを許可する。WindowsもOSで通知を無効にしていると届かない。「常に通知する」はOSの集中モードを解除する設定ではない。

Macの通知は `.app` として起動した場合に利用できる。未パッケージの開発用実行ファイルではOSの通知センターを呼ばず、設定画面に利用できない旨を表示する。

「テスト通知を送る」は「通知しない」を選んでいても使える。送信成功はOSへの引き渡しを意味し、画面に表示された保証ではない。

通知をクリックすると起動中のTanzakooを前面へ戻し、対象の会話を開く。別のAI処理・プロジェクト切り替えが進行中なら会話を切り替えない。終了済みアプリを起動して会話を復元する仕組みは含めない。

## 実装と依存

- Rustの応答保存後に一度だけ判定する。通知エラーは会話の成否に影響させない。画面側のイベント再購読では再送しない。
- Windows: Tauriが保守する `tauri-winrt-notification` 0.8.1（MIT OR Apache-2.0）とMicrosoftの `windows` 0.62系を使用。MSIXのAUMIDはOSから取得する。開発用などパッケージなしの起動では、Tanzakoo自身のID・表示名だけをユーザーの `Software\Classes\AppUserModelId` に登録する。管理者権限は不要。
- Windowsの初回送信前に `ToastNotifier.Setting` が `ERROR_NOT_FOUND` を返す場合は、許可済みと断定せず `unknown` として送信を試みる。明示的なOSの無効設定は引き続き尊重する。ネイティブ送信と通知センターへの1件の登録をWindows上で確認済み。
- Mac: `objc2-user-notifications` 0.3.2（Zlib OR Apache-2.0 OR MIT）と `block2` 0.6.2を使用し、UserNotificationsで許可・送信・フォアグラウンド表示・クリックを処理する。リモートプッシュや通知サーバーは使わない。
- Tauriの汎用通知プラグインは使わない。デスクトップの許可APIが常に許可済みを返す点とクリック処理を避け、対象OSのAPIを利用する。

## 配布物での確認項目

Windows MSIXと署名済みMacアプリの実機で以下を確認する。Windows上の自動テストやMacモジュールのクロス型検査だけでは、OSの表示・許可ダイアログまで検証したことにならない。

1. 設定の3択が再起動・プロジェクト切り替え後も保持される。
2. 非アクティブ時のみ: 別アプリ・最小化中は通知され、アクティブ時は通知されない。常に通知: アクティブでも通知される。
3. 質問を返す正常応答も1回だけ通知。停止・エラー・履歴再表示では通知されない。
4. Macの未許可状態からユーザー操作で許可ダイアログが出る。拒否後は繰り返し要求せず、OS設定の変更が設定画面へ戻ると反映される。
5. テスト通知、OSでの通知無効、集中モード、通知クリック、別の応答実行中のクリックを確認する。
6. Windows MSIXで通知元がTanzakooになり、インストールごとのパッケージIDを推測していないことを確認する。

参考: [TauriのWindows通知ライブラリ](https://docs.rs/tauri-winrt-notification/0.8.1/tauri_winrt_notification/)、[Appleの通知許可](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications)。
