# Tanzakoo — AIを任意で使う設計案

更新：2026-09-16

## 合意済みの前提

手作業でもアイデアを整理できるローカルアプリに、任意でAI支援を接続する。

ユーザーの「いいね。いったんこれ前提で詰めてみてもらっていい？」を受けた設計メモ。その後の実装依頼により、下記の範囲を実装した。ストア審査通過を示すものではない。

## 実装した範囲（2026-09-16）

- 空ボードの手動作成の入口、チャット開閉、閉じている間の下書き保持。
- 明示的な接続確認、チャット内の接続エラー、プロジェクト・エージェントごとの送信同意。
- CodexのNode・ACPアダプター・本体の同梱、ブラウザ認証の開始・サインアウト、アプリ専用の認証保存先。
- 接続確認と認証ではプロジェクト内容を渡さず、会話も作成しない。接続処理の停止と、その間のプロジェクト切り替えの禁止。

Windowsでは同梱実行環境による接続確認まで検証済み。本人によるブラウザ認証完了、新しい専用アカウント領域での会話、MacのSandbox・署名、MSIXは未検証／未実装。Claudeの配布版ログインは[公式の提供条件](https://code.claude.com/docs/en/agent-sdk/overview)を確認するまで保留し、APIキー方式への変更も未合意。

以下は設計時点の検討内容を残したもの。最新の実装・検証結果は [実装・検証メモ](implementation-progress.md) を参照。

ボードを正本とすること、1カード1論点、自動起票は候補、既存情報へのAIの変更は承認を経ることは維持する。AIとの壁打ちは引き続き中心的な体験の一つとする。

## アプリとして提供する体験

説明文の案：

> 思いつきをカードにして、検討したいことや決めたことを整理するローカルワークスペース。必要なときはAIと話しながら、論点や要求を具体化できます。

| 機能                                           | AI未接続での扱い                       |
| ---------------------------------------------- | -------------------------------------- |
| プロジェクト作成・切り替え、名前・メモリの編集 | 利用できる                             |
| カード作成・編集・検索・列移動・並べ替え       | 利用できる                             |
| カード削除・復元                               | 利用できる                             |
| 保存済みの会話履歴の閲覧                       | 利用できる。ログインを求めない         |
| 保存済みの変更提案の適用・却下                 | 利用できる。既存のリビジョン確認を行う |
| 新しいAI応答・自動起票・変更提案の生成         | 利用可能なエージェント接続が必要       |

全体を切り替える「手動モード／AIモード」は設けない。同じプロジェクト・ボードを、AIを使う前も使った後もそのまま編集する。

## 初回起動と画面

1. アカウント・Node・エージェントの設定を要求せず、ボードを開く。
2. 空のボードに「最初のカードを作る」を主導線、「AIと考える」を副導線として置く。AIから始める入口も残す。
3. 「最初のカードを作る」はタイトルだけで保存できる。本文はカード詳細で追記する。
4. 「AIと考える」でチャットを開き、未設定なら接続案内を表示する。設定を閉じても、カード作成や編集は続けられる。

基本の3領域（ボード・カード詳細・チャット）は維持する。チャットは開閉でき、閉じた分をボードと詳細に割り当てる。初回の未設定時はチャットを閉じ、以降は開閉状態を記憶する案。

既存の列「アイデアの山／検討する／話し合う／決めたこと」は当面維持。「話し合う」はAI接続を必要とする状態にはせず、自分で考えたり人と相談したりしている論点にも使える。列名変更は別の検討とする。

## チャットと接続状態

接続設定の有無と、実際に会話できることを区別する。既定の起動コマンドが存在するだけで「接続済み」と表示しない。

| 状態                     | チャットでの表示・操作                                             |
| ------------------------ | ------------------------------------------------------------------ |
| 未設定                   | AIが任意である説明と「AIを設定」。履歴があれば閲覧可能             |
| 設定あり・未確認         | 「接続を確認」。前回の成功だけで現在の利用可否を保証しない         |
| 確認中                   | チャット内に進捗・中止を表示。ボードの通常操作は維持               |
| サインインが必要         | 対応する認証手順を案内。入力中の文章や履歴を保持                   |
| 利用可能                 | 新しい会話・送信・カード参照を利用可能にする                       |
| 接続失敗・利用上限など   | 理由と再試行・設定への導線をチャット内に表示                       |
| 配布版で接続方式が非対応 | 対応範囲を明示。未設定とは区別し、使えないセットアップへ誘導しない |

「利用可能」は確認時点の状態。送信時の失敗にも対応する。エラーを判別できない場合は推測で認証切れとせず、一般的な接続エラーと詳細を示す。

接続確認は利用者の操作で行い、プロジェクト内容を送信しない。ボードや履歴を開くだけではエージェントを起動しない。初回の内容送信前には、送信先と対象（現在のプロジェクトのボード・メモリ・会話・参照）を説明し、同意を得る案。具体的な認証・確認方法はアダプターごとの検証が必要。

会話の続きは元のエージェントへ送る。利用できなくなっても履歴は読める。別のエージェントを使う場合は新しい会話にする既存方針を維持する。

参照添付はローカルでの準備に留め、送信操作まで外部に渡さない。AI未設定時にカードから参照した場合は、チャットを開いて参照を保持し、設定の導線を示す案。

実行中のプロジェクト切り替えは、現在どおり停止完了後に許可する。接続確認を追加するときも、対象プロジェクトの固定と停止・失敗後のロック解除を検証する。

## 現状との差分

2026-09-16にソースを確認した結果。エージェント未導入環境での新たな実機試験は、この設計作業では行っていない。

- `src-tauri/src/lib.rs`：起動・DB読み込み・カード操作と、`send_prompt` から始まるエージェント実行は分かれている。保存済み提案の適用もローカル処理。
- `src/components/Board.tsx`：手動追加・検索・列移動・並べ替え・削除済みカードの復元がある。
- `src/components/CardDetails.tsx`：手動編集・保存・削除・提案の承認がある。
- `src/components/Projects.tsx`：プロジェクト作成・切り替え・メモリ編集がある。
- `src/App.tsx`：3ペインが常時表示され、チャット開閉はまだない。
- `src/components/Chat.tsx`：未設定・認証待ちなどの接続状態を表示する仕組みがなく、AIへ話しかける入口が基本になっている。
- `src/components/Settings.tsx`：実行ファイル・JSON引数の設定が中心。一般利用者向けの設定導線が必要。
- `src/lib/workspace.ts`：送信失敗をアプリ共通エラーにも表示している。接続の問題をチャット内で扱い、保存エラーと区別する必要がある。
- `src-tauri/src/agent.rs`：開発元の `node_modules` または外部コマンドに依存する既定設定。配布用の起動経路は別途整備する。

## 配布とNodeの位置づけ

基本機能の利用に、利用者によるNodeやエージェントの導入を要求しない。AIを提供する配布物では、必要なランタイムの同梱方式を別途決める。Nodeを同梱するかどうかで保存データの形式や基本機能を変えない。

- AI込みの配布：現在のJavaScript版ACPアダプターを使うなら、専用Nodeと必要な依存をアプリとともに更新する構成が候補。エージェント本体の再配布条件・認証・署名も検証する。
- AIを含めない配布：基本機能はNodeなしで成立する。ただし、この版を実際に作るかは未決。
- Mac App Store：単体で役立つことと、AI接続部分がSandbox等を満たすことを別々に確認する。AIが任意であるだけでは後者は解決しない。

まず共通のアプリでAIなしの体験を完成させる。ストア版・直接配布版の機能差やAPIキー方式への変更は、Macでの接続検証後に判断する。現時点で製品を複数版に分けることや、独自のクラウド中継サービスの採用は決めない。

根拠と限界（2026-09-16確認）：

- [Apple審査ガイドライン §4.2.3](https://developer.apple.com/app-store/review/guidelines/#minimum-functionality)：別アプリの導入なしで単独動作することを要求。上の構成が説明しやすいというのは設計上の見立てであり、審査結果の保証ではない。
- [同 §2.4.5](https://developer.apple.com/app-store/review/guidelines/#hardware-compatibility)：Mac版のSandbox・自己完結したバンドル等の条件がある。
- [同 §2.3.1](https://developer.apple.com/app-store/review/guidelines/#accurate-metadata)：含める機能は説明・審査可能にする。任意のAI機能も審査対象として準備する。
- [Tauri: Node.js as a sidecar](https://v2.tauri.app/learn/sidecar-nodejs/)：NodeランタイムとJavaScriptリソースを同梱する構成を案内している。Mac App Store対応の証明ではない。

## 推奨する次の実装範囲

1. AI未導入の環境で基本機能が完結することを確認し、空ボードの導線とチャット開閉を整える。
2. 接続状態・設定・送信前の説明を設計して実装し、エージェント不在・認証切れ・失敗から戻れるようにする。
3. 配布用のランタイム構成を試作し、WindowsパッケージとMac Sandboxで起動・認証・会話の実現性を検証する。

バックアップ／復元とMarkdown書き出しは、蓄積した内容を持ち出せるようにする次の候補。既存の実装範囲には含まれておらず、今回の前提変更に便乗して必須化しない。

受け入れ確認案：

- Node・両エージェントを利用できずネットワークもない環境で、起動→プロジェクト作成→カード追加・編集・整理→メモリ編集→終了・再起動まで完結する。
- AIで作成したデータがあっても、エージェントなしで履歴を読み、保存済み提案を確認・適用できる。古い提案による上書きは防ぐ。
- 起動・プロジェクト切り替え・履歴閲覧では、エージェントの子プロセス起動やAIへの送信が発生しない。
- 接続失敗・中止後も、入力途中の文章・カード・履歴が残り、ボード操作とプロジェクト切り替えを再開できる。
- 手動で作ったカードを後からAIへ参照でき、自動起票・変更提案・承認の既存の往復が維持される。
