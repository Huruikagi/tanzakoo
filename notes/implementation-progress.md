# 初版の実装・検証

## 対象

- Tauri + Reactによるボード・カード詳細・チャット。
- SQLite保存、候補追加・列移動・削除と復元。
- Markdown編集とカード全体・選択範囲の参照添付。
- AIの候補自動起票、既存カードの変更提案と適用・却下。
- Codex / ClaudeへのACP接続、応答表示、キャンセル、接続失敗の表示。
- 選択したエージェントで会話を再開。保存したボードが正本。
- プロジェクトごとのDB分離、名前・メモリの編集、メモリ変更提案と承認。
- mise管理、Oxlint / Oxfmt / @shadcn/lint、適切なテストと起動確認。
- GitHubリポジトリへ初版を保存。

## 実装上の選択

- 既存カードへのAI変更は提案として保存し、適用時に対象のリビジョンを確認する。
- エージェント用MCPには候補の作成・ボードの取得・変更提案を提供する。確定操作は公開しない。
- プロジェクトごとにDBとエージェント作業ディレクトリを分離する。既存の `tanzakoo.db` と作業ディレクトリは移動せず、一覧DBに最初のプロジェクトとして登録する。
- 画面からの保存・送信は対象のプロジェクトIDを明示する。切り替えと実行開始を同じロックで保護し、切り替え前の操作が別のDBへ書き込まれないようにする。
- メモリの取得・変更提案もMCPで扱う。直接編集と提案適用はリビジョンを確認し、AIには確定操作を公開しない。
- ローカルDBの操作を共通Rustモジュールに置き、TauriとMCPの双方から利用する。
- 本文はMarkdownで編集し、参照にはカードID・リビジョン・引用を含める。
- dnd kitの先行DOM並べ替えは、非同期の保存結果をReactに反映するタイミングと衝突した。`onDragOver` の `preventDefault()` で先行並べ替えを抑止し、保存後に表示順を反映する。ドラッグ・衝突判定・キーボード操作はライブラリを使う。[公式の状態管理ガイド](https://dndkit.com/react/guides/sortable-state-management/)

### 実装

- 初回はチャットを閉じて手動作成から始められる。チャットの開閉状態を記憶し、非表示中も下書き・参照・応答を保持する。

## Claude接続の提供条件と共通処理（2026-09-16）

依頼：既存のClaude契約で使える構成を第一候補に、提供条件を確認し、適合する方式なら実装する。APIキー方式・独自の中継は未合意。

### 判断

- **提供条件は未解決。サブスクリプション接続を正式対応として実装・表示しない。** 詳細・根拠・問い合わせ文案（未送信）は [Claude接続の提供条件](claude-connection-terms.md)。
- Legal and complianceには「利用者本人が改変していないClaude Codeへ自分の契約でサインインすることは妨げない」とある。一方、同ページとAgent SDK資料は、Agent SDKを使う第三者製品にAPIキー認証を求め、事前承認なしのclaude.aiログイン提供を認めていない。Tanzakooは独自UI・指示・MCPからSDK経由でClaude Codeを駆動するため後者に近く、前者の例外に入るとは資料から判断できない。
- 既存アダプターの動作・他製品の採用・ヘルプ記事の利用枠説明は、提供許可の根拠にしていない。
- 同梱はCommercial Termsへの同意、バイナリ無改変、組み込み認証方法を制限しないことが条件。配布者の判断が必要なため、Claudeは同梱していない（`packages/agent-runtime` はCodexのみ）。

### 記録と現行コードの区別

- 過去の記録「Claude実接続で会話・起票・変更提案を確認」は、開発環境の `node_modules` のアダプターと開発者自身のClaude Codeログインによるもの。今回、実アカウントでの会話は再検証していない。
- 現行コードで確認：Claudeの既定設定は開発依存の `claude-agent-acp`（0.77.0 → Agent SDK 0.3.270 → 同梱 `claude.exe` 2.1.270）。認証はアダプターのターミナル認証（`claude auth login`）で、Tanzakooは対応を宣言していない。認証情報は既定で `~/.claude`。

### 実装

- 配布（release）ビルドの既定では、Claude設定を「非提供」（`@tanzakoo/claude-unavailable`）にする。子プロセスを起動せず、チャットでは提供していない旨を表示し、接続確認・サインイン・送信を出さない。開発依存のアダプターへのフォールバックはdebugビルドに限定。
- Claudeのサインイン・サインアウト要求は、プロセスを起動せず `unsupported` を返す。画面のサインインボタンはCodexに限定。
- 開発用の外部Claude接続の確認：`initialize` と空のセッション作成だけを行い、プロジェクト内容・MCP・プロンプトを送らない。アダプターの `_auth/status_update` から、未ログイン／サブスクリプション／APIキー（月額契約とは別の従量課金）／外部の接続先を表示する。メールアドレスは表示・保存しない。
- テスト対象のファイルを `src` に限定。`.local/` の検証データ（Codexが作った一時ファイル）が `pnpm check` を失敗させていたため。
- 新しい依存関係は追加していない。
