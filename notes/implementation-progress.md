# 初版の実装・検証

## 対象

- Tauri + Reactによるボード・カード詳細・チャット。
- SQLite保存、候補追加・列移動・削除と復元。
- Markdown編集とカード全体・選択範囲の参照添付。
- AIの候補自動起票、既存カードの変更提案と適用・却下。
- Codex / ClaudeへのACP接続、応答表示、キャンセル、接続失敗の表示。
- 選択したエージェントで会話を再開。保存したボードが正本。
- プロジェクトごとのDB分離、名前・メモリの編集、メモリ変更提案と承認。
- mise管理、Oxlint / Oxfmt / @shadcn/lint、適切なテストと起動確認。
- GitHubリポジトリへ初版を保存。

### 残している確認・制限

- 前回保留したデスクトップの通し確認は完了。再開時にはWindowsのNode.jsファイアウォール確認は残っておらず、ビルド済みアプリの検証でOS設定の変更は必要なかった。
- 初版の動作確認はWindows。macOS / Linuxは未検証。
- セッション復元対応時はACPのload_sessionを利用する。復元自体がエラーになった場合は接続エラーを表示し、新しい会話から再開する。履歴移植は行わない。
- 未保存の下書きはメモリ上に保持し、終了後は残さない。
- 本文の差分ハイライト、自動関連順、同一プロジェクト内の複数ボード、インストーラー配布は未実装。複数プロジェクトは対応済み。
- プロジェクトの削除・エクスポート・インポート・横断検索は未実装。エージェント実行中のプロジェクト切り替え・作成は、停止処理が終わるまで禁止する。
- Viteビルドは成功するが、JavaScriptの単一チャンクが約1.2MBでサイズ警告が出る。初版はローカル配信で、分割は今後の改善点。
- RustのWindowsリンク時に日本語のライブラリ生成メッセージがwarningとして出る場合がある。コンパイルとClippyは成功する。

## 実装上の選択

- 既存カードへのAI変更は提案として保存し、適用時に対象のリビジョンを確認する。
- エージェント用MCPには候補の作成・ボードの取得・変更提案を提供する。確定操作は公開しない。
- プロジェクトごとにDBとエージェント作業ディレクトリを分離する。既存の `tanzakoo.db` と作業ディレクトリは移動せず、一覧DBに最初のプロジェクトとして登録する。
- 画面からの保存・送信は対象のプロジェクトIDを明示する。切り替えと実行開始を同じロックで保護し、切り替え前の操作が別のDBへ書き込まれないようにする。
- メモリの取得・変更提案もMCPで扱う。直接編集と提案適用はリビジョンを確認し、AIには確定操作を公開しない。
- ローカルDBの操作を共通Rustモジュールに置き、TauriとMCPの双方から利用する。
- 本文はMarkdownで編集し、参照にはカードID・リビジョン・引用を含める。
- dnd kitの先行DOM並べ替えは、非同期の保存結果をReactに反映するタイミングと衝突した。`onDragOver` の `preventDefault()` で先行並べ替えを抑止し、保存後に表示順を反映する。ドラッグ・衝突判定・キーボード操作はライブラリを使う。[公式の状態管理ガイド](https://dndkit.com/react/guides/sortable-state-management/)
