# Tanzakoo

曖昧なプロダクトアイデアを、カード操作と必要に応じたAIとの対話で少しずつ具体化するローカルツール。AIなしでもプロジェクト・カード・メモリを作成して整理できます。

**会話から論点が生まれる → 気になるカードを選ぶ → 内容を指して話す → 提案を確認して適用する。**

初版のプロトタイプです。Tauri 2 / React / TypeScript / Rustを使い、CodexへACPで接続します。

## 起動

WindowsではRustのMSVCツールチェーン、Visual StudioのC++ビルドツール、WebView2、miseが必要です。
Nodeとpnpmは `mise.toml` のバージョンを使います。

```powershell
mise trust
mise install
mise exec -- pnpm install --frozen-lockfile
mise exec -- pnpm tauri dev
```

「AIと考える」→「接続状況」→「ChatGPTで続ける」からSign in with ChatGPTで接続します。AI利用は本人のChatGPT利用枠を消費します。Tanzakooは無料で、APIキーは不要です。開発時はmiseのNodeとプロジェクト依存を利用します。

設定は「一般」と「AI接続」に分かれています。接続中はアカウントと利用量への入口を表示し、切り替え・再サインイン・サインアウトは「アカウント管理」から行います。送信の説明と同意の取り消しは「送信する内容と同意」にまとめています。

通常接続はChatGPTに統一し、内部の実行エンジンには同梱Codex・ACPを使います。保存済みの旧Codex・Claude会話は履歴として閲覧できます。過去の調査は [Claude接続の提供条件](notes/claude-connection-terms.md) に残しています。

`mise exec -- pnpm dev` だけでも画面をプレビューできます。ブラウザプレビューでは保存とエージェント接続は利用できません。

開発サーバーを使わずに起動する場合は、画面を内蔵した実行ファイルを作れます。

```powershell
mise exec -- pnpm tauri build --debug --no-bundle
mise exec -- .\src-tauri\target\debug\tanzakoo.exe
```

この実行ファイルも、エージェント接続にはプロジェクト内のNode依存を使います。単体配布用ではありません。

### Node・Codexを同梱するビルド

```powershell
mise exec -- pnpm runtime:stage
mise exec -- pnpm build:desktop
```

`runtime:stage` はビルドを実行したOS・CPU向けの依存をpnpm deployで固定ロックファイルからまとめ、miseのNodeとライセンス表示を同梱します。生成先は `src-tauri/resources/agent-runtime`。再生成時はこの生成フォルダーだけを削除してから実行します。

Windowsでは出力された実行ファイルと、その隣の `agent-runtime` フォルダーを一緒に配置します。開発用Node・CodexをPATHから外した条件で起動確認済みです。MSIXの作成手順と検証用パッケージを用意しました。Microsoft Storeの登録と配信は未実施です。[Windowsストア提出準備](notes/windows-store/README.md) を参照してください。

Mac版はApple Silicon・macOS 26 Tahoe以上を対象に、署名・公証済みDMGで直接配布します。GitHub Actionsの手動実行ワークフロー `macOS signed DMG` で生成し、公証と検証が成功したDMGだけを成果物に保存します。2026-09-26に初回の署名・公証・DMG内ランタイム検証が成功しました。Finderからの起動やブラウザ認証などの操作確認は別途必要です。Secrets・実行手順・検証範囲は [Macの署名・公証とDMG作成](notes/macos-distribution.md) を参照してください。

## 使い方

設定（歯車）の「表示言語」で「システムに合わせる／日本語／English」を選べます。全プロジェクト共通で保存し、自動ではOSの言語が日本語なら日本語、それ以外は英語になります。切り替えても保存済みのカード・メモリ・会話や、起動中の下書きは変更しません。AIはユーザーの希望する言語、指定がなければ発言の言語に合わせます。審査員向けの手順は英語のみの [Store review notes](notes/store-review-notes.md) にまとめています。

上部のプロジェクト選択から作業対象を切り替えます。その横の「＋」でプロジェクトを作成し、「メモリ」で名前とMarkdownの前提メモを編集できます。

1. 「カード」から手動で始められます。AIを使う場合は「AIと考える」でチャットを開き、接続を確認して、初回だけ送信への同意を行ってから話しかけます。送信はボタンまたは **Ctrl + Enter**。
2. エージェントが論点を「アイデアの山」に自動起票します。初期段階では複数の切り口を候補に残します。さらに増やしたいときは、列見出しの「話題を広げる」で既存カードを見ながら3〜5枚ほど追加できます。全部を片付ける必要はなく、放置しても消えません。
3. 気になるカードを開き、本文を編集します。列の移動はドラッグか、詳細の列選択から行えます。
4. 「会話に参照」でカード全体を添付できます。本文を範囲選択すると「選択範囲を参照」も使えます。編集中の内容は先に保存します。
5. 変更提案はカード詳細の差分で、削除（赤・−）と追加（緑・＋）、変更された文言を確認できます。「変更後」で完成形を読み、適用または却下します。メモリの提案も同じ表示です。承認前に元の内容は変わりません。
6. 不要なカードは削除できます。ボード右上のアーカイブから復元できます。

チャットの「＋」で新しい会話を開始します。会話途中でエージェントは切り替えず、会話履歴から再開できます。
AIから1〜4個の質問がまとめて提示されたら、質問ごとに選択肢を選ぶか「自分で回答する」で文章を入力します。前の質問へ戻って修正でき、全問がそろったら「まとめて送信」で会話を続けます。入力中のチャット本文と添付参照は残ります。質問への未送信の回答は起動中の画面切り替えで保持しますが、アプリ終了では消えます。通常のチャット入力から別の話を続けると、その質問の回答受付は終了します。回答は会話の希望として扱い、カードやメモリの変更は引き続き提案の承認が必要です。
未回答の質問は入力欄の上に固定され、「回答待ち」→全問入力後の「送信待ち」と表示が変わります。回答済みは履歴内の折りたたみから確認できます。質問への回答中は「未承認の変更」を件数表示にまとめ、クリックすると一覧を開いて確認・承認できます。

「自分で回答する」を押すと入力欄までスクロールします。自由入力中はCtrl＋Enter（MacはCommand＋Enterも可）で次の未回答質問へ進み、全問の回答がそろっていれば送信します。Enterだけなら改行します。質問が1問のときは番号や残り件数の案内を省き、「回答を送信」で会話を続けられます。
チャットは開閉でき、閉じても起動中の下書きは保持します。接続確認・ログイン・ログアウトではプロジェクト内容やプロンプトを渡しません。保存済みの会話と変更提案は未接続でも閲覧・適用できます。

ChatGPTの認証情報とセッションはアプリ保存先の `chatgpt-plan` に保存します。このフォルダーを共有・Git登録しないでください。認証と送信への同意は全プロジェクト共通です。同意は `projects.db` に保存し、接続設定から取り消せます。最後に使ったアカウントは再起動時に自動復元します。サインアウト済み・認証失効・通信失敗の場合は接続状況から再接続してください。別アカウントには自動で切り替えません。旧Codex接続の会話は閲覧できますが、ChatGPT接続での会話は新しく始めます。
カードを切り替えても編集途中の下書きは保持します。ただし、未保存の下書きはアプリを終了すると消えます。

### カード同士をつなぐ

カードの編集欄で「カードリンクを挿入」を押し、同じプロジェクトのカードを検索して選ぶと、カーソル位置にリンクが入ります。保存後、プレビューのリンクから参照先を開けます。名前を変更してもリンクは切れず、表示は最新のタイトルに追従します。

参照先の詳細には「このカードを参照しているカード」が表示され、元の話題へ戻れます。編集中の下書きはカードを切り替えても保持されます。AIも起票や変更提案にリンクを含められます。アーカイブ済みの参照先は、その旨を表示して閲覧できます。

### プロジェクトとメモリ

- プロジェクトごとにボード・会話履歴・メモリ・変更提案を分けます。既存のボードは最初の「マイプロジェクト」として引き継ぎます。
- メモリには概要、目的、利用者、制約、AIへの進め方の指示などを残せます。新しい会話でも、送信時に現在のメモリを渡します。
- メモリは直接編集できます。AIに更新を頼んだ場合は「メモリ」に変更提案の件数が表示され、内容を確認して適用・却下できます。個別の論点と結論はカードに残します。
- 最後に開いたプロジェクトと、プロジェクトごとのカード・会話の選択を復元します。カード、メモリ、チャットの下書きは起動中の切り替えでも保持しますが、アプリ終了後には残りません。送信前の参照添付は切り替え時に解除します。
- エージェントの応答中はプロジェクトを切り替えられません。応答を待つか停止してから切り替えます。
- 新しいプロジェクトの接続設定は作成元から引き継ぎ、その後はプロジェクトごとに編集できます。

## 保存とエージェントに渡す内容

### プロダクトの資料を参照して壁打ちする

画面上部の「参照資料」から「ファイルを追加」「フォルダーを追加」でソースコードやMarkdownを登録できます。ファイルはその1件、フォルダーは配下を対象とし、登録はこのプロジェクトの次の会話・再起動にも引き継ぎます。他のプロジェクトには共有しません。

AIは必要な箇所だけを検索・読み取り、ファイル名と行番号を根拠に改善案を話し合います。元ファイルは編集せず、コマンドも実行しません。登録だけでは送信せず、会話でAIが読む内容をOpenAIへ送信します。元ファイルの変更は次の読み取りに反映します。

初版はUTF-8のテキスト（1ファイル1MiB以下）、登録は32件までです。`.git`・`node_modules`・`target`・`dist`・`build`などの成果物、`.env`や秘密鍵、リンクは対象外です。PDF・画像・その他のバイナリは読めません。検索結果や長い行は上限で省略する場合があり、その場合はAIへ省略を通知します。

「解除」は次回以降のアクセスを止めます。元ファイルや過去の会話に渡した内容は削除しません。AI処理中は停止または完了後に追加・解除できます。移動・削除された資料は解除し、必要なら新しい場所を登録してください。

### 保存される情報

- 正本はプロジェクトごとのSQLite DBです。Windowsの既定保存先は `%LOCALAPPDATA%\dev.huruikagi.tanzakoo`。MacはOSから取得するApplication Support内の `dev.huruikagi.tanzakoo` を使い、Sandbox版ではアプリのコンテナ内になります。最初のDBは直下の `tanzakoo.db`、追加したプロジェクトは `projects/<保存用ID>/tanzakoo.db` に保存します。一覧・保存先・最後に開いたプロジェクトは `projects.db` で管理します。
- カード、提案、会話、プロジェクト名・メモリ、接続設定をローカル保存します。保存先のルートは起動時の `TANZAKOO_DATA_DIR` で変更でき、相対指定は起動時に絶対パスへ解決します。Sandboxの制限を回避する指定ではありません。
- 未リリースのため旧 `%APPDATA%` 配置からの自動移行は行いません。既存の開発データを使う場合は、そのフォルダーを `TANZAKOO_DATA_DIR` に指定してください。旧フォルダーを自動で移動・削除することはありません。
- 各プロジェクトにボードが一つあります。プロジェクト横断検索、候補の自動消去、自動並べ替え、クラウド同期はありません。
- エージェントにはユーザーの発言、現在のプロジェクト名・メモリ・ボード、明示的な参照を渡します。会話を新規セッションで復元するときは同じ会話の最近の履歴も渡します。利用先のアカウント・契約条件が適用されます。
- TanzakooのMCPツールは「ボード・メモリ取得」「候補作成」「議論中カードの報告」「カード変更提案」「メモリ変更提案」「選択肢の提示」「登録済み参照資料の一覧・検索・読み取り」です。これらは自動許可します。既存カード・メモリへの変更適用、選択肢への回答、参照資料の登録・解除はUIから行います。
- 同梱Codexのシェル・通常のファイル閲覧・画像閲覧などのツールは無効にし、専用ツール以外の権限要求は拒否します。読み取り専用設定によりファイル編集も拒否します。
- 提案後にカードが更新されていたら、その提案は適用できません。最新の内容を確認して再提案を依頼します。

バックアップする場合はアプリとエージェントを終了してから、一覧DBを含む保存先のフォルダー全体をコピーしてください。プロジェクト全体のインポート・復元機能はまだありません。

Mac版の対象はApple Silicon・macOS 26 Tahoe以上です。Windowsの正式配布はMSIXによるMicrosoft Store公開を予定しています（パッケージ作成は検証段階、Store配信は未実施）。ストア向けの保存・ファイル権限の設定と、署名後に必要な検証は [ストア配布の保存設計](notes/store-storage.md) を参照してください。

## 決めたことを開発に渡す

画面上部の「エクスポート」から「保存先を選んで出力」を押すと、選んだ保存先に新しいフォルダーを作ります。

```text
tanzakoo-プロジェクト名-出力時刻/
  index.md           読み方と決定事項へのリンク
  project.md         プロジェクトメモリ（背景・前提）
  decisions/
    0001-話題名.md    「決めたこと」の各カード
    0002-話題名.md
```

このフォルダーを開発用プロジェクトに置き、「index.mdから背景と決定事項を読み、アプリの実装を進めて」と開発エージェントへ渡せます。カード本文は要約せずに保存し、カードリンクは出力したファイルへの通常の相対Markdownリンクに変換します。参照先が未決定・アーカイブ済みなどで出力対象外の場合は、理由を添えた文字として残します。

出力は [OKF v0.2](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/main/SPEC.md) のMarkdown形式です。入口の `index.md` に `okf_version: "0.2"`、プロジェクトと各カードの先頭にYAMLメタデータを付けます。`type` は `Tanzakoo Project` / `Tanzakoo Decision`、`title` は保存済みの名前・タイトルです。`tanzakoo` 配下には `project_id`・`revision`、カードにはさらに `card_id` を記録します。決定済みであることを検証済みとみなさず、`verified` は付けません。

カードのファイル名は、人が内容と順序を把握できる「連番＋タイトル」を使います。改題や並べ替えで出力時のパスは変わりますが、元のカードはメタデータのIDで対応付けられます。

出力対象は「決めたこと」の削除されていないカードと、保存済みのプロジェクトメモリです。未保存の編集は先に保存してください。未適用の提案や会話履歴、ほかの列のカードは含みません。毎回別のフォルダーを作るため、過去の出力は上書きしません。出力は保存先選択を始めた時点の内容で、ボードの変更とは同期しません。

## 応答完了の通知

AIの応答完了時の通知は、設定の「一般」で選べます。初期値は「非アクティブ時のみ」です。Macでは通知許可が必要です。「テスト通知を送る」で確認できます。詳しい動作と配布物での確認項目は [デスクトップ通知](notes/desktop-notifications.md) を参照してください。

## 開発と検証

```powershell
mise exec -- pnpm check
mise exec -- pnpm test:runtime
mise exec -- pnpm test:plan
mise exec -- pnpm test:review
cargo fmt --manifest-path src-tauri/Cargo.toml --check
mise exec -- cargo test --manifest-path src-tauri/Cargo.toml --locked
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --locked -- -D warnings
```

- Oxlint + Oxfmt。`@shadcn/lint` の `no-restyle` で共通部品の利用を確認します。レイアウト調整と動的スタイルは許容します。
- Vitest / React Testing Libraryで参照・下書き・送信・提案適用を検証します。
- Rustのテストで保存、承認時の競合検出、許可対象、キャンセル状態を検証します。認証のテストではmiseのNodeで模擬ACPエージェントを起動します。`ts-rs` によるTypeScript型も生成します。
- `test:review` は審査用仲介の境界と、実Codex・ACP・MCPを使う候補作成・変更提案・会話復元をローカル模擬APIで検証します。Rustで現在の本体をビルドします。実APIの費用は発生しません。公開仲介に接続するアプリは `TANZAKOO_REVIEW_URL` を指定してビルドします。詳細は [審査用仲介の手順と制限](packages/review-relay/README.md) を参照してください。
- 実ChatGPT接続の確認はアプリで行います。手順と確認済み項目は [ChatGPTプラン接続](notes/chatgpt-plan-preview.md) を参照してください。`scripts/agent-smoke.ps1` は旧認証を使う内部エンジンの診断用で、現在の通常接続の検証には使いません。

Claudeのアダプターと検証コードは将来の調査用に残していますが、現在の画面からは利用しません。通常の開発で実接続の検証は不要です。調査を再開する場合、未ログイン時の確認には、空のフォルダーを `CLAUDE_CONFIG_DIR` に指定し、`ANTHROPIC_API_KEY` を設定しない状態で次を実行できます。

```powershell
$env:CLAUDE_CONFIG_DIR = (New-Item -ItemType Directory -Force .local/claude-empty-config).FullName
mise exec -- cargo test --manifest-path src-tauri/Cargo.toml --locked --test agent_connection -- --ignored real_claude
```

Mac・Windowsの掲載原稿、審査メモ、画像選定と提出資料の生成手順は [Mac掲載資料](notes/app-store/README.md) と [Windowsストア提出準備](notes/windows-store/README.md) にまとめています。

公開済みの配布物はまだありません。ソースから起動するか、Macの署名・公証ワークフローの検証済み成果物を使用してください。
詳細な検証結果と残りの確認は [実装・検証メモ](notes/implementation-progress.md) を参照してください。
通常のAI接続はSign in with ChatGPTです。`mise.exe exec -- pnpm tauri dev` で起動でき、追加のfeature指定は不要です。APIのプレビュー仕様への追従と配布物での確認は継続します。詳細は [ChatGPTプラン接続](notes/chatgpt-plan-preview.md) を参照してください。

## 依存関係の更新

[Dependabot設定](.github/dependabot.yml)で、npm（pnpm workspace）・Rust・GitHub Actionsを毎週月曜9時（日本時間）に確認します。minor / patchはnpmの開発ツール、npmの画面・実行時、Rust、Actionsの4グループにまとめます。Reactの型、Tauri CLI、ACPアダプターはnpmの画面・実行時グループに含めます。

major更新は個別PRとし、通常更新の同時オープン数はnpm 3件・Rust 2件・Actions 2件（合計最大7件）に制限します。セキュリティ更新はecosystemごとの別グループで、この上限とは別枠です。セキュリティPRにはGitHub側のDependabot alerts / security updatesの有効化も必要です。

取り込みはプロジェクト用Skill [tanzakoo-merge-dependabot](.agents/skills/tanzakoo-merge-dependabot/SKILL.md)に依頼できます。

```text
$tanzakoo-merge-dependabot DependabotのPRを確認して、検証が通ったものを順にマージして。
```

Skillは変更内容・互換性・最新コミットのCIを確認し、1件ずつマージして次のPRを再確認します。「確認だけ」と依頼した場合はマージしません。

2026-09-27時点の[GitHub公式対応表](https://docs.github.com/en/code-security/reference/supply-chain-security/supported-ecosystems-and-repositories)にはpnpm 7〜10が記載され、本プロジェクトのpnpm 12は記載されていません。設定をデフォルトブランチに反映後、Dependabotの更新ログと最初のnpm PRでworkspace・ロックファイルの更新可否を確認してください。対応不足の場合はエラーを記録して手動更新を検討し、Dependabotに合わせてpnpmを自動的にダウングレードしません。`mise.toml` のNode / pnpm更新はこの設定の監視対象外です。
